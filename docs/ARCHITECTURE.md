# Архитектура Conductor

## Роли

| Слой | Кто | Модель | Отвечает за |
|---|---|---|---|
| Оркестратор | основная сессия + скилл `conduct` | Opus (Fable по выбору) | триаж, ТЗ, план, решения, синтез, арбитраж, финальный текст |
| Сборщики | `scout`, `reader`, `finder`, `formatter`, `cartographer` | Haiku | объём: поиск, чтение, локализация кода, форматирование, карточки |
| Исполнители | `builder`, `analyst` | Sonnet | код по спецификации, расчёты скриптами |
| Проверяющие | `fact-checker`, `code-verifier` | Sonnet | независимая проверка в свежем контексте |
| Детерминированный слой | `scripts/*.py` + хуки | без модели | карта проекта, реестр утверждений, гейт, учёт токенов |

Принцип: модель делает только то, что требует суждения. Всё, что можно посчитать скриптом (индексация, поиск зависимостей, проверка ссылок, учёт токенов), считает скрипт.

Почему проверяет Sonnet, а не Haiku: проверка смысла (поддерживает ли абзац утверждение, совпадают ли определения) — самая важная операция против галлюцинаций. Экономить на ней невыгодно. Haiku собирает доказательства, Sonnet их оценивает, Opus разрешает конфликты.

## Жизненный цикл задачи (run)

```
.conductor/runs/<дата-время-slug>/
  state.json     фаза, номер раунда, гейт
  spec.md        ТЗ (EN)
  evidence/      записи scout/reader/analyst (jsonl, та же схема, что у реестра)
  analysis/      скрипты analyst
  reports/       отчёты проверяющих по раундам
  claims.jsonl   реестр утверждений (текущие версии)
  verdicts.jsonl журнал вердиктов, каждый привязан к отпечатку версии утверждения
  draft.md       черновик с метками [Cn] и [~]
  final.md       итог с нумерованными источниками (пишет только finalize)
```

Фазы: `planning → producing → verifying ⇄ producing → delivering → done` (плюс `awaiting_user`, `aborted`). В `done` задача переходит только через `runs.py finalize`.

## Хуки

| Событие | Скрипт | Стоимость | Что делает |
|---|---|---|---|
| SessionStart | `codemap.py hook-session-start` | 0 токенов модели на работу, ≤ ~1 тыс. токенов контекста | инкрементальная синхронизация карты по mtime/size, вставка MAP.md и короткой инструкции |
| PostToolUse (Edit/Write/MultiEdit/NotebookEdit) | `codemap.py hook-post-edit` | одна строка контекста | переиндексация файла, список зависимых файлов, пометка карточки STALE |
| Stop | `runs.py hook-stop` | 0, если нет активного run | блокирует завершение хода, если в активном run остались pending/refuted утверждения или задача в фазе delivering не финализирована (не более 3 раз подряд, уважает `stop_hook_active`) |
| Stop (async) | `usage.py hook-stop` | 0 | пересчёт токенов сессии из транскриптов |
| SubagentStop (async) | `usage.py hook-subagent-stop` | 0 | сопоставление agent_id → тип агента для отчёта |

В проектах без `.conductor/` все хуки молча завершаются, плагин ничего не добавляет в контекст.

## Ограничения платформы, учтённые в дизайне

- Субагенты из плагина не поддерживают `hooks`, `mcpServers` и `permissionMode` во frontmatter. Поэтому хуки живут в `hooks/hooks.json` плагина.
- `AskUserQuestion` недоступен субагентам: вопросы пользователю задаёт только оркестратор.
- Встроенный агент Explore работает на модели основной сессии (Opus). Протокол направляет поиск по коду в `conductor:finder` на Haiku.
- По умолчанию одновременно может работать до 20 субагентов. Conductor ограничивает параллелизм тремя (`parallel.max_agents`), чтобы не сжигать лимит всплеском.
- Описания всех субагентов постоянно занимают контекст, поэтому они короткие, а детали — в теле агента, которое загружается только при запуске.
