# Разметка проекта и инкрементальная индексация

## Задача

Убрать повторные сканирования проекта моделью. При изменении файла должна обновляться и читаться только связанная информация.

## Три уровня

1. **`map.json`** — машинный граф: для каждого файла хеш, модуль, исходящие зависимости, теги, mtime/size. Пишет и читает только скрипт; модель его не открывает.
2. **`MAP.md`** — компактный индекс модулей: размер, зависимости между модулями, статус карточки, назначение одной строкой. Вставляется в контекст в начале сессии (лимит `codemap.session_map_chars`, по умолчанию 4000 символов).
3. **`cards/<модуль>.md`** — карточка модуля до 60 строк: назначение, публичный интерфейс, инварианты и решения, список файлов. Пишет `cartographer` (Haiku), читается только при работе с модулем.

Модель читает сверху вниз и останавливается, как только информации достаточно.

## Что происходит при правке

```
Edit src/net/lobby.ts
  └─ PostToolUse → codemap.py hook-post-edit
       ├─ пересчёт хеша и импортов только этого файла
       ├─ модуль src/net → STALE
       └─ в контекст (1 строка): «зависимые для проверки: src/ui/menu.ts, src/game/session.ts»
```

При создании нового файла скрипт заново разрешает ранее не найденные импорты, которые могут на него указывать. Импорт, написанный до появления модуля, связывается сразу, как только модуль создан.

В начале следующей сессии `sync` переиндексирует только файлы с изменившимися mtime/size, включая правки из IDE и `git pull`. Карточки STALE обновляются по требованию и только для затронутых модулей.

## Карта — первый источник, а не единственный

Динамические импорты, сгенерированный код и языки без аннотаций карта может не увидеть. Поэтому правило такое: начинать с карты и карточек, а если ответа нет, расширять поиск по шагам (папка модуля → связанные модули → точечный поиск по всему репозиторию). Читать проект целиком не нужно.

## Распознавание зависимостей

| Язык/формат | Как |
|---|---|
| Python | `import` / `from … import`, включая относительные |
| JS/TS/Vue/Svelte | `import`, `require`, `export … from`, динамический `import()`, алиас `@/` → `src/` |
| Godot | `preload/load/extends("res://…")`, ресурсы в `.tscn/.tres` |
| Markdown | относительные ссылки, `[[вики-ссылки]]` как теги |
| HTML | `src` / `href` |
| Любой другой (C#/Unity, C++, Go, SQL…) | аннотация в комментарии: `@map: depends=путь1, путь2` и `@map: tags=…` |

Группировка по модулям автоматическая (`src/<x>`, `Assets/<x>`, папка первого уровня) и переопределяется glob-шаблонами в `.conductor/config.json`.

## Исследования и аналитика

Те же механизмы работают для `.md`, `.csv`, `.sql`, `.ipynb`. Карточки служат базой проверенных знаний проекта: одна тема — одна карточка, только подтверждённые факты с URL и датой. Связи между заметками задаются относительными ссылками, и тогда `impact` показывает, какие выводы затронет изменение.
